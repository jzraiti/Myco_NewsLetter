# Milestone v1.1: Frontend Performance and UI Improvements

**Status:** SHIPPED 2026-04-12
**Phases:** 5-7
**Total Plans:** 10

## Overview

Milestone `v1.1` improved the public frontend experience without changing the core product direction. It moved JUFO browsing off the browser-heavy CSV path, rebuilt the article and newsletter archives around canonical server-backed pagination, and polished the touched public pages so they feel clearer, more readable, more mobile-safe, and more accessible while preserving the background-image-driven visual identity.

## Phases

### Phase 5: JUFO Server-Backed Browsing

**Goal**: Visitors can open and explore JUFO rankings through a fast server-backed flow instead of loading the full dataset into browser memory.
**Depends on**: Phase 4
**Plans**: 2 plans

Plans:

- [x] 05-01: Normalize the canonical JUFO dataset and add a tested server paging adapter.
- [x] 05-02: Rebuild `/jufo` around the server adapter with URL-driven controls and end-to-end coverage.

**Details:**
- Replaced browser-owned JUFO CSV parsing with a repo-owned normalized artifact and server-only paging adapter.
- Rebuilt `/jufo` as a server-backed route with URL-driven search and pagination.
- Added regression coverage proving JUFO browsing works without browser CSV requests.

### Phase 6: URL-Driven Archive Pagination

**Goal**: Visitors can browse article and newsletter archives through stable, shareable, server-backed pagination.
**Depends on**: Phase 4
**Plans**: 3 plans

Plans:

- [x] 06-01: Create the shared paginated archive data helpers, contracts, and deterministic multi-page fixtures.
- [x] 06-02: Rewire `/articles` to server-backed URL pagination with search-state persistence and acceptance coverage.
- [x] 06-03: Rewire `/newsletters` to server-backed numbered pagination with shareable page URLs and acceptance coverage.

**Details:**
- Added one shared archive pagination contract and fixed page size for `articles` and `newsletters`.
- Rebuilt `/articles` around canonical `q/page` URL state, server-side pagination, and empty-state recovery.
- Rebuilt `/newsletters` around canonical paginated URLs, numbered navigation, and stable current-page feedback.

### Phase 7: Public UI Clarity, Responsiveness & Accessibility

**Goal**: Visitors get a more polished and readable public frontend across touched pages while preserving the background-image-driven visual identity.
**Depends on**: Phase 5 and Phase 6
**Plans**: 5 plans

Plans:

- [x] 07-01: Establish shared public-shell styling, navigation cues, and accessibility foundations.
- [x] 07-02: Polish the home subscribe and unsubscribe flows with stronger hierarchy and clearer destructive-state handling.
- [x] 07-03: Refresh the articles archive framing, cards, and mobile/search accessibility without changing Phase 6 behavior.
- [x] 07-04: Refresh the newsletters archive framing, cards, and responsive pagination clarity.
- [x] 07-05: Reframe JUFO browse/search surfaces for readable tables, mobile usability, and accessible state feedback.

**Details:**
- Added route-aware navigation, skip links, and stronger shared focus treatment across public pages.
- Polished subscribe/unsubscribe flows with clearer hierarchy and safer destructive-state handling.
- Refined article, newsletter, and JUFO surfaces for stronger readability, mobile usability, and accessible interaction feedback.
- Added a dedicated mobile JUFO card presentation while preserving the server-backed JUFO contract.

## Milestone Summary

**Decimal Phases:**

- None

**Key Decisions:**

- Keep JUFO and archive browsing server-backed rather than reintroducing browser-owned full-dataset state.
- Use canonical URL-driven pagination and search state so archive flows are refreshable, shareable, and testable.
- Preserve the background-image identity while improving readability through stronger surfaces, hierarchy, and accessibility cues.
- Use route-aware shared navigation, skip links, and dedicated mobile JUFO cards as the public-shell/accessibility baseline.

**Issues Resolved:**

- Eliminated browser-heavy JUFO CSV parsing and the associated memory/performance problem.
- Removed fetch-all archive pagination behavior and replaced it with real paginated server queries.
- Improved public-page hierarchy, mobile usability, and focus/interaction feedback across the touched frontend routes.

**Issues Deferred:**

- Year-based archive grouping or jump-point discovery.
- Richer JUFO filter controls beyond fast browse/search.
- JUFO row expansion or richer on-demand detail views.

**Technical Debt Incurred:**

- Milestone closeout automation still required manual cleanup because the archive CLI left some milestone docs in a stale state.
